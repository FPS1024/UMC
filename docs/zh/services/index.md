# 可选服务

UMC 提供一组可以独立部署的配套服务。它们都不是安装或启动 Minecraft 的必需组件，社区和启动器开发者可以只运行自己需要的部分。

每个服务都有自己的 Docker 镜像，可以放在启动器旁边、同一个 HTTPS 反向代理后面，或者部署在另一台服务器上。

| 服务 | 状态 | 用途 |
|---|---|---|
| [UMC Auth](./auth) | 初步实现 | 账号注册和 Yggdrasil 兼容认证 |
| [镜像站](./mirror) | 计划中 | 版本、库、资源和 Java 运行时的下载镜像 |
| [皮肤设计器](./skindesigner) | 计划中 | Web 皮肤编辑器和纹理托管 |

## 设计原则

- **默认可选。** 普通 UMC 安装不会主动连接这些服务。
- **独立部署。** 每个服务有自己的 Docker 镜像、配置和数据存储。
- **HTTPS 优先。** 公开服务应放在负责 TLS 的反向代理后面。
- **社区自持。** 账号、下载内容和纹理都由运营者控制。
- **小范围。** 每个服务只做一件事，并暴露有文档的 API，而不是做成大型管理平台。

## 如何选择

- 如果玩家需要在你自己的网站上注册，并通过 authlib-injector 或其他兼容 Yggdrasil 的启动器进入服务器，请运行 **UMC Auth**。
- 如果社区访问 Mojang 下载源较慢或不稳定，可以运行**镜像站**。
- 如果希望玩家用同一套账号编辑和上传皮肤，可以运行**皮肤设计器**。

[UMC Auth 指南](./auth)介绍部署、管理后台、邀请码、可选邮箱验证、Turnstile、工作量证明、限流以及 HTTPS 部署检查。
